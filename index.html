Umami, from the tracker to the dashboard

Umami is a privacy-focused, cookieless web analytics app: a small tracker script posts page views and events to one collection endpoint, a Next.js server turns each hit into a row, and every dashboard number is a SQL query over those rows — on PostgreSQL, or on ClickHouse at scale. These guides explain how; the code in umami-software/umami (version 3.4.1 as read for these pages) is always the source of truth.

🔑

The one mental model: a visitor is a hash, not a record. There are no cookies and no visitor table keyed by a browser id. Every hit to POST /api/send recomputes session_id = uuid(website, ip, user-agent, monthly salt) and visit_id = uuid(session, hourly salt), then writes one website_event row. A hit's life is short:

received validated session + visit derived stored as website_event dropped: bot → {beep: boop} 403: IGNORE_IP 400: schema / unknown website

Everything else — sessions, visits, channels, funnels, revenue — is derived from those rows at query time. Start with Session & visit identity once you have read the foundations.
