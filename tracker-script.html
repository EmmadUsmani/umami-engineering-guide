The tracker script

What does the browser actually send, when, and what makes it stay silent? src/tracker/index.ts is a single IIFE, built to public/script.js, that reads its configuration from its own <script> tag.

1 · Configuration 2 · Opt-outs 3 · SPA navigation 4 · Cache token 5 · Click events 6 · JS API

1Every option is a data- attribute on the script tag itself

The tracker finds itself through document.currentScript — if that is null (e.g. the code was injected and run later), it does nothing at all.

<script defer src="https://analytics.example.com/script.js"
        data-website-id="e676c9b4-11e4-4ef1-a4d7-87001773e9f2"
        data-domains="example.com,www.example.com"
        data-do-not-track="true"
        data-performance="true"></script>
AttributeDefaultEffect
data-website-id—Required; without it nothing is sent
data-host-urlbuild-time COLLECT_API_HOST, else the script's own directoryWhere to POST
data-auto-trackon"false" disables page views, SPA hooks and click tracking entirely
data-auto-pageviewon"false" keeps click tracking but skips automatic page views
data-domainsanyComma list; other hostnames are ignored
data-do-not-trackoff"true" makes the browser's DNT setting count
data-exclude-search / data-exclude-hashoffStrip query or fragment before sending — which also hides UTM tags from channel attribution
data-before-send—Name of a global function that may rewrite or drop each payload
data-tag, data-distinct-id—Attach a tag to every event; identify the visitor immediately
data-performanceoff"true" sends Web Vitals as type: 'performance'
data-fetch-credentialsomitPassed straight to fetch

2Five checks can silence the tracker before every send

Do-Not-Track is opt-in for the site owner: the browser's DNT flag is ignored unless the tag says data-do-not-track="true".

const trackingDisabled = () =>
  disabled ||
  !website ||
  localStorage?.getItem('umami.disabled') ||
  (domain && !domains.includes(hostname)) ||
  (dnt && hasDoNotTrack());
💡

To exclude your own visits, run localStorage.setItem('umami.disabled', '1') on the tracked site. Any non-empty value works; the check is truthiness.

ℹ️

The tracker honours a disabled flag in the collection response, but src/app/api/send/route.ts in this repo never returns one — it answers { cache, sessionId, visitId } (or { beep: 'boop' } for bots). Treat disabled as a hook for other collectors, not as something this server does.

3Single-page apps are tracked by wrapping history.pushState and replaceState

After the original method runs, the hook makes the previous URL the new referrer and schedules a page view 300 ms later.

const handlePush = (_state: unknown, _title: string, url?: string | URL | null) => {
  if (!url) return;

  if (typeof flushPerformance === 'function') {
    flushPerformance();
  }

  currentRef = currentUrl;
  currentUrl = normalize(url);

  if (currentUrl !== currentRef && autoPageview) {
    setTimeout(track, delayDuration); // 300 ms
  }
};

Two consequences: replaceState calls that change the URL count as page views too, and the 300 ms delay lets frameworks update document.title first. Back/forward navigation (popstate) is not hooked. Same-origin referrers are reduced to a path by stripOrigin, and the server then drops the referrer domain for self-referrals (flow step 7), which is why internal page views carry no referrer domain.

4The tracker round-trips a server-signed token so repeat hits skip work

The response's cache JWT is stored in a closure variable and replayed as x-umami-cache; it lives as long as the page does.

const res = await fetch(endpoint, {
  keepalive: true,
  method: 'POST',
  body: JSON.stringify({ type, payload }),
  headers: {
    'Content-Type': 'application/json',
    'x-umami-website-id': website as string,
    'x-umami-hostname': hostname,
    ...(typeof cache !== 'undefined' && { 'x-umami-cache': cache }),
  },
  credentials,
});

const data = (await res.json()) as { cache?: string; disabled?: boolean } | null;
if (data) {
  disabled = !!data.disabled;
  cache = data.cache;
}
First hit on a page load
No header. The server looks the website up and, on Postgres, creates the session row.
fetchWebsite · createSession
Later hits
The token's websiteId skips the website lookup; its visitId/iat pin the visit for up to 30 minutes (details).
parseToken(cacheHeader, secret())
identify()
Sets the token to '' before sending, which the server treats as no token — the identified hit gets a freshly derived session (the distinct id is in the hash) and visit.
cache = ''
Full page reload
The closure is gone, so the first hit is uncached again — but because ids are recomputed, the session and (within the hour) the visit come out the same.
no storage used for the token
🔑

The token is an optimisation, not identity. It is never written to localStorage or a cookie; losing it costs a database lookup, not a session. Identity comes from the hash in Session & visit identity.

5Tracked links wait for the event before navigating

A capturing click listener looks for the nearest ancestor with data-umami-event; every data-umami-event-* attribute becomes event data.

Clicked elementBehaviour
Non-link elementtrack(name, data), no interference with the click
<a href>, same tabpreventDefault(), await the send, then set location.href (or top.location for target="_top")
<a> with target="_blank", Ctrl/Shift/Meta, or middle buttonTracked without blocking the browser's own navigation
⚠️

Because same-tab links wait for send(), a slow or unreachable collector delays navigation for every tracked link until the request settles. fetch has no timeout here.

6The JS API is three functions on window.umami

umami.track()
No args: a page view of the current URL. A string: a custom event (event_type = 2) with optional data. An object: sent as the whole payload. A function: receives the default payload and returns one.
umami.identify()
identify('user-123', data) or identify({ id, …data }); sends type: 'identify' and remembers the id for later payloads.
umami.getSession()
Returns { cache, website } — handy when debugging the token flow.

Unit tests for all of this live next to the source in src/tracker/index.test.ts.
