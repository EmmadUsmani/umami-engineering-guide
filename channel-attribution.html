Channel attribution

How does a visit end up labelled paidAds, organicSocial or direct? Nothing is stored: a SQL CASE classifies every event at query time — and Umami carries six copies of that CASE that do not all agree.

🔑

A channel is computed, not stored. Changing the rule re-labels all historical data the next time a report runs — and because the rule is copied six times, a change to one copy silently splits the reports.

1Twelve WHEN branches, first true one wins

The inputs are five website_event columns written by /api/send: referrer_domain, url_query, utm_medium, utm_source, hostname.

WITH prefix AS (
  select case when website_event.utm_medium LIKE 'p%' OR
      website_event.utm_medium LIKE '%ppc%' OR
      website_event.utm_medium LIKE '%retargeting%' OR
      website_event.utm_medium LIKE '%paid%' then 'paid' else 'organic' end prefix,
  ...
channels as (
  select case
      when referrer_domain = '' and url_query = '' then 'direct'
      when ${toPostgresLikeClause('url_query', PAID_AD_PARAMS)} then 'paidAds'
      when ${toPostgresLikeClause('utm_medium', ['referral', 'app', 'link'])} then 'referral'
      when utm_medium ilike '%affiliate%' then 'affiliate'
      when utm_medium ilike '%sms%' or utm_source ilike '%sms%' then 'sms'
      when ${toPostgresLikeClause('referrer_domain', LLM_DOMAINS)} then 'llm'
      when ${toPostgresLikeClause('referrer_domain', SEARCH_DOMAINS)} or utm_medium ilike '%organic%' then concat(prefix, 'Search')
      when ${toPostgresLikeClause('referrer_domain', SOCIAL_DOMAINS)} then concat(prefix, 'Social')
      when ${toPostgresLikeClause('referrer_domain', EMAIL_DOMAINS)} or utm_medium ilike '%mail%' then 'email'
      when ${toPostgresLikeClause('referrer_domain', SHOPPING_DOMAINS)} or utm_medium ilike '%shop%' then concat(prefix, 'Shopping')
      when ${toPostgresLikeClause('referrer_domain', VIDEO_DOMAINS)} or utm_medium ilike '%video%' then concat(prefix, 'Video')
      when referrer_domain != regexp_replace(hostname, '^www.', '') and referrer_domain != '' then 'referral'
      else '' end AS x,

3Six copies of the rule exist, and the Postgres channel report is the odd one out

Three query files × two dialects. Their WHEN lists match; their paid/organic prefix and their fallback do not.

-- getChannelMetrics.ts, Postgres (case-sensitive LIKE, anchored 'p%')
case when utm_medium LIKE 'p%' OR utm_medium LIKE '%ppc%' OR ... then 'paid' else 'organic' end

-- revenue/getRevenueMetrics.ts, Postgres (case-insensitive, substring '%cp%')
case when we.utm_medium ilike '%cp%' OR we.utm_medium ilike '%ppc%' OR ... then 'paid' else 'organic' end

-- every ClickHouse copy (lowercased substring 'cp')
case when multiSearchAny(lower(utm_medium), ['cp', 'ppc', 'retargeting', 'paid']) != 0 then 'paid' else 'organic' end

4On Postgres, a missing referrer is NULL, so the "direct" branch never fires for it

/api/send leaves referrerDomain undefined when there is no referrer (or it is a self-referral), so Prisma stores NULL — while url_query is ''.

NULL = '' is NULL, not true, so WHEN #1 is skipped and every later test against referrer_domain is also NULL. Persona carol still ends up direct, but by the fallback coalesce(nullif(x, ''), 'direct'), not by branch #1 — the resolver's trace shows the ? marks. The difference becomes visible when the row has UTM columns but an empty or NULL query string, which the tracker never produces but scripts/seed does (it writes urlQuery: null for every event): the seed: newsletter / email preset is email in the Postgres channels report and direct everywhere else.

ℹ️

Because the seed script puts UTM values in columns but never in url_query, branch #2 (paidAds) can never fire on seeded Postgres data. Seeded dashboards under-report paidAds compared with tracker-collected data; do not use them to sanity-check channel changes. Use the API suite's personas instead (codebase · tests).

6A visit takes the first non-empty channel of its events

The channels report counts sessions per channel after collapsing each visit to one label.

visit_channels as (
  select session_id, visit_id, coalesce(nullif(x, ''), 'direct') as x
  from (
    select x, session_id, visit_id,
      row_number() over (
        partition by session_id, visit_id
        order by case when x != '' then 0 else 1 end, created_at, event_id
      ) as row_num
    from channels
  ) as ranked_channels
  where row_num = 1)

select x, count(distinct session_id) y

Only the landing page view normally carries a referrer, so the visit inherits its channel; later page views (internal referrer → NULL) classify as '' and sort last. ClickHouse does the same with argMin(x, tuple(if(x != '', 0, 1), created_at, event_id)). The revenue report instead takes the session's earliest event (min(created_at)) and classifies that one row. Since visit_id is derived per hour (session identity), a long browsing session can contain several visits, each attributed separately.
