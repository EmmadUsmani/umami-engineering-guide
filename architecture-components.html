Architecture · components

What is Umami made of? One Next.js application — UI, REST API, collection endpoint and MCP server in a single deployable — in front of PostgreSQL, with ClickHouse, Kafka and Redis as opt-in add-ons switched on by environment variables.

🔑

There is one deployable. Collection, dashboard API, UI and MCP all run in the same Next.js process; the only architectural switch is runQuery choosing Postgres or ClickHouse per call, based on CLICKHOUSE_URL.

2Four doors into the server, and only the collect door skips auth

Every handler calls parseRequest (src/lib/request.ts), which validates with zod and then runs checkAuth — unless the route passes { skipAuth: true }, as /api/send does.

checkAuth (src/lib/auth.ts) tries, in order: an API key (if the bearer token looks like one), a signed JWT carrying userId, a Redis-backed authKey, then a share token — which is only honoured alongside the share-context header. A 2FA partial-auth token is rejected outright. Flow detail: login and share page.

3One function decides which database answers every analytics query

runQuery in src/lib/db.ts is the whole backend switch. Each SQL module hands it one closure per backend.

export async function runQuery(queries: any) {
  if (process.env.CLICKHOUSE_URL) {
    if (queries[KAFKA]) {
      return queries[KAFKA]();
    }

    return queries[CLICKHOUSE]();
  }

  const db = getDatabaseType();

  if (db === POSTGRESQL) {
    return queries[PRISMA]();
  }
}
export async function getChannelMetrics(...args: [websiteId: string, filters?: QueryFilters]) {
  return runQuery({
    [PRISMA]: () => relationalQuery(...args),
    [CLICKHOUSE]: () => clickhouseQuery(...args),
  });
}
⚠️

Two SQL dialects, kept in sync by hand. Every module in src/queries/sql/ carries a Postgres string and a ClickHouse string for the same metric. Nothing checks that they agree; Channel attribution documents a live case where they do not. Change both, and test both (pnpm test:api and pnpm test:api:clickhouse).

Note the precedence: any CLICKHOUSE_URL routes analytics reads and event writes to ClickHouse, while Prisma still owns users, teams, websites and the other CRUD tables on Postgres.
